# Gobierno del conocimiento

## Objetivo

Evitar que ONE dependa de memoria de chats o que el proyecto cambie de significado según la conversación más reciente.

## Reglas

1. Las afirmaciones fundacionales viven en el vault.
2. Los chats pueden proponer cambios; el vault los vuelve durables.
3. Una hipótesis no se promueve a hecho por repetición.
4. Una decisión reemplazada se conserva históricamente y se marca superseded.
5. Las mediciones negativas se guardan igual que las positivas.
6. Los benchmarks deben registrar configuración, artifact hashes, hardware, comandos y límites cuando empiece la implementación.
7. Las varas técnicas fijadas para una campaña no se reducen cuando aparezcan dificultades.
8. Tampoco se inflan retrospectivamente si ONE empieza a cumplirlas. Los criterios técnicos se fijan antes de las campañas comparativas.
9. Herramientas de IA se documentan solo cuando sea útil para reproducibilidad o proceso; no se tratan como una categoría moral distinta de herramientas.
10. Si una idea del chat no está en el vault y es importante, se considera frágil hasta migrarla.

## Versionado

Este vault comienza en **0.1.0**. Cambios arquitectónicos importantes incrementan minor; correcciones editoriales patch. Una eventual 1.0 debe corresponder a una arquitectura implementada y defendible, no solo a documentación madura.
